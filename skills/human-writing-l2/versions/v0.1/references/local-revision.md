# Local Revision｜局部去模型化返修

> 只用于 LOCAL_REVISION。没有具体病灶，不启动。

## 0. 先保护活着的地方

改稿前先保护三类内容：

- 最像当前人物本人会说、会想、会做的地方；
- 最能让读者追下一步的地方；
- 看起来不够漂亮，却正在快速完成必要叙事的地方。

后续修改默认不碰它们，除非存在真值错误、视角越界、无效重复或明确误读。

## 1. 返修输入必须具体

必须至少有：

```text
LOCATION
PROBLEM
MINIMUM REPAIR TARGET
```

例如：

```text
LOCATION: 三证据冲突后的两段
PROBLEM: 已经通过数据表现出矛盾，随后又总结一次，解释重复
TARGET: 删除第二层结论，不改变主角下一动作
```

“整体更自然”“去 AI 味”“润色一下”不足以触发全文修改。

## 2. 修改范围

优先：

```text
KEEP
DELETE
COMPRESS
MERGE
FLATTEN
LOCAL RECAST
```

只修改命中区域和确实需要连带调整的相邻文字。

禁止：

```text
WHOLE-CHAPTER REWRITE
GLOBAL HUMANIZATION
GLOBAL SYNONYMIZATION
VOICE NORMALIZATION
PARAGRAPH NORMALIZATION
RANDOM COLLOQUIALIZATION
DETECTION-RATE OPTIMIZATION
```

## 3. 四类过度解决优先“删与停”

### 即时验真

异常已能通过后续现实证据确认时，首次异常附近多余的：

- 旧状态对照；
- 排除眼花；
- 连续内视；
- 再次确认；
- 来源分析；

优先删到“看见 + 一个直接反应”或“一项必要检查”。

### 证据集齐

人物已经有足够依据采取下一动作后，第二、第三层同功能证明优先压缩、后置或删除。

### 问题问完

决定已经形成后，后续不改变决定、关系、风险、筹码的问题优先删除。

### 重复结算

结果已经通过行动 / 对方反应 / 现实后果成立后，后续心理复盘、原话对照、意义总结、章尾再宣布，通常只留最有力一层。

## 4. 处理“模型解释腔”

重点看解释是否在重复翻译读者已经能看懂的结构。

常见信号：

- “这意味着……”；
- “也就是说……”；
- “他终于明白……”；
- “事情已经变成了……”；
- “至少有一点可以确定……”；
- “再解释下去只会……”；
- “这并不是……而是……”。

它们不是禁词。

如果承担新信息或人物真实判断，可以保留；如果只是给已经成立的动作和结果再盖章，就删或压平。

## 5. 处理“过度工整”

症状包括：

- 连续多个短句都承担落锤；
- 连续多个单句段；
- 每段都有结论；
- 每个新信息都配动作 + 心理 + 解释；
- 每轮对白都恰好问对问题、答完整答案；
- 句子和段落受力点过分均匀。

修复目标不是故意变乱，而是恢复语义驱动的自然差异。

## 6. 处理“采访式对白”

如果删掉中间一两个低信息问句，持有话语权的人仍然会自然继续表达，就优先合并。

如果问答不改变：

- 请求；
- 筹码；
- 许可；
- 期限；
- 关系；
- 退路；
- 现场动作；

而只是把信息搜全，允许停在人物已经够用的位置。

## 7. 处理“约束墓碑”

正文出现“没有突破 / 没有恢复 / 没继续试 / 奖励没增加 / 期限没变”等句子时，先问：

> 这个“没有发生”是否改变下一动作或代价？

如果没有，只是在向工作流证明“禁令已遵守”，删除。

## 8. Truth Guard

返修不得改变：

- 事件顺序与结果；
- 人物知识边界；
- 已批准人物选择；
- 数字 / 能力 / 资源 / 物品状态；
- 世界规则；
- 章尾 stop；
- 未授权未来信息。

如果局部修复做不到而必须改结构，停止并上报。

## 9. 结束条件

病灶已经消失，且相邻文字自然、真值未变，就停止。

不要因为“既然已经改到这里”继续优化下一段。
