# Web Fiction Core｜商业网文不完整权限

## 0. 第一原则

商业网文的活人感主要来自：

> **作者持续取舍，人物只处理眼前够用的东西，正文没有把所有分析逐项展示。**

主因果要成立，正文表面不需要处处闭环。

## 1. 一个主要变化就可以托住一章

章节需要真实变化，但不需要每个小问题都解决。

有效变化可以是：

- 下一步做法改变；
- 新人物被卷进来；
- 关系位置改变；
- 多一项承诺；
- 一个误会开始影响现实；
- 资源 / 风险 / 暴露发生变化；
- 新信息直接改变行动；
- 主角被拖进下一步。

不要因为一章只有一个主要变化，就自动补第二个危机、第二次验证、第二场冲突。

## 2. 局部允许悬空

允许：

- 问题没有当场回答；
- 误会没有立刻澄清；
- 一次试探没得出结论；
- 小矛盾只是临时压住；
- 人物知道事情不对，但先不处理；
- 对话结束时双方仍没有共识；
- 读者已经懂，人物还没完全懂；
- 事情只解决一半，本章先停。

只要这些不破坏硬事实、主因果和章尾已锁结果，就不是漏洞。

> **故事底下可以闭合，正文表面不要处处闭合。**

## 3. 三种延迟

### 认知延迟

看到异常，可以先只觉得怪，不马上知道意义。

### 回应延迟

听到一句话，可以先没接、答偏、敷衍，过一会儿才回到它。

### 解决延迟

知道有问题，也可以先做眼前别的事，或者只临时处理。

延迟不是模板。不要每次都强行加喝水、看窗、沉默三秒。

## 4. 人物只想到够行动的位置

停止点：

> **已经足以决定下一步。**

允许人物：

- 判断不完整；
- 暂时误解；
- 懒得解释；
- 改口；
- 嘴硬；
- 说漏嘴；
- 撒一个不够高明的小谎；
- 没接住全部问题；
- 只关心自己眼前一点；
- 暂时不做决定。

不为了“真人感”随机降智。

## 5. 四个过度解决刹车

### A. 即时验真

异常第一次出现时，不默认连续执行：

```text
再看一次
→ 排除错觉
→ 检查身体 / 设备
→ 对照旧状态
→ 再次验证
→ 下真伪结论
```

如果后文已有现实证据、第二次结果或他人反应，自然确认即可。

第一次通常只需要：

```text
异常进入感知
+ 一个最自然的直接反应
```

只有下一步必须先判断真假，才保留一项最自然检查。够行动就停。

### B. 证据集齐

材料里有 A / B / C，不等于正文必须：

```text
发现 A → 分析 A
发现 B → 分析 B
发现 C → 总结 ABC
```

人物拿到足够行动依据后，剩余痕迹可以：

- 一句带过；
- 后置；
- 当背景；
- 不写；
- 留到以后。

```text
MATERIAL_COMPLETE != EVIDENCE_CHAIN_VISIBLE
```

### C. 问题问完

人物已经有足够信息决定离开、拒绝、答应、换办法后，不继续把“还能问的问题”逐项问完。

允许：

- 不知道；
- 没问；
- 对方没答；
- 含糊过去；
- 人物已经不在乎。

场景完整不等于信息完整。

### D. 重复结算

一个结果已经通过动作、关系变化、交易变化、对方改口或现实后果让读者看懂后，不再依次补：

```text
心理复盘
→ 原话对照
→ 一句小总结
→ 章尾意义宣布
```

通常只留最有力的一层。

## 6. 对白允许没效率

对白不要求每句都增加硬信息。

允许：

- 回答一半；
- 回避；
- 打断；
- 误会；
- 敷衍；
- 夹带旧账；
- 嘴硬；
- 答非所问；
- 说到一半改口；
- 一句只负责关系；
- 少量属于熟人的废话。

但不能整章都变成无承重闲聊。

## 6.5 Interaction Completion != Semantic Completion

一次人物交流已经完成，不等于这次交流里的所有意思都必须被说完整。

人物开口首先是在做当前的人际动作，例如：

- 拒绝；
- 结束话题；
- 推开解释；
- 试探；
- 敷衍；
- 留余地；
- 逼对方表态；
- 保护自己；
- 把关系往前或往后推一步。

只要这项动作已经完成，对白不欠读者一份完整的“立场 + 原因 + 情绪名称 + 结论”。

例如人物说“算了，你不用解释了”，如果当前场景已经让失望与关系变化成立，就不需要自动追加一段“我并不是不相信你，只是……”式完整说明。

反过来也一样：如果人物此刻确实需要解释、说服或交代，他可以一口气说完整，不得为了“真人感”硬截成半句话。

```text
INTERACTION_COMPLETE
!= ALL_MEANING_EXPLICIT
```

禁止把以下东西变成新模板：

- 高频“我……”；
- 高频“不是，就是……”；
- 高频“算了”；
- 随机语气词；
- 每场都故意答非所问。

不完整表达必须来自人物关系、当下目的和现场压力，而不是配额。

## 7. 按“话语权”组织对白

对白基本单位不是一句多长，而是：

> **这一刻谁还握着话语权，他有没有理由继续说。**

如果一个人物正在解释、抱怨、说服、定条件，对方中间那些“嗯？”“真的？”“为什么？”并没有改变方向，就不必硬拆成很多问答小包。

允许一口气说两三句，也允许只说一个字。

真正需要变化的是回合重量，不是长短句配额。

## 8. 回应不必语言化

一句话落下来以后，对方可以：

- 没接；
- 看一眼；
- 继续手上的事；
- 推回一个已有物件；
- 笑一下；
- 过一会儿再提；
- 直接用下一动作回答。

不要把每个刺激都翻译成一句口头确认。

## 9. 结构桥梁可以不说完

如果动作、对白和前后顺序已经让读者能接上因果，不需要叙述者再逐句翻译：

- “他意识到……”；
- “这意味着……”；
- “他终于明白……”；
- “事情已经变成了……”；
- “再解释下去只会……”。

这些不是绝对禁句。只有当它们在重复翻译已经可见的结构时才删。

## 10. 禁止“约束墓碑”

输入里写了“不突破 / 不恢复 / 不解决 / 不暴露 / 不继续验证”，正文不需要主动写：

- “他没有继续试”；
- “奖励并没有增加”；
- “旧问题依旧存在”；
- “期限没有变化”；

除非这个“没有发生”本身会改变下一动作或代价。

禁写项不需要在正文里留下墓碑。

## 11. 开始和停止只是切口

开头不是仪式，结尾不是总结考试。

只要当前章主要变化已经发生，stop 没越界，正文可以停在：

- 一个动作；
- 一句对白；
- 一个关系位置；
- 一个具体结果；
- 一个余波；
- 一个仍然没有答案的问题。

不负责把所有意义都结算完。
