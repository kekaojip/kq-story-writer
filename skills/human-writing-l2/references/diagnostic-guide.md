# Diagnostic Guide｜只报警，不拥有改文权

## 0. 定位

诊断只能提供证据，不能决定“有报警就必须修改”。

```text
DIAGNOSTIC != VERDICT
FLAG != AUTO-EDIT
```

所有报警都必须回到上下文判断。

## 1. 重点观察

### 1.1 连续漂亮闭合

观察是否高频出现：

- “所以 / 也就是说 / 这意味着 / 总之 / 至少有一点可以确定”；
- 短句落锤后立刻空行；
- 每段结尾都像一句可摘录结论。

### 1.2 句长和段落过度规整

观察：

- 连续短句；
- 连续单句段；
- 句长波动异常小；
- 段落大小像模板切出来。

不能为了提高方差随机改句长。

### 1.3 转折 / 反转句形过密

例如：

- “不是……而是……”；
- “并非……而是……”；
- “看似……其实……”；
- “真正……的是……”；
- “不重要，重要的是……”；
- “以为……后来才发现……”。

这些句式本身合法，问题是密度和功能重复。

### 1.4 模型路标

例如：

- “值得注意的是”；
- “需要指出的是”；
- “从某种意义上说”；
- “还有一层”；
- “更微妙的是”。

角色口吻或确有新信息时可以保留。

### 1.5 采访式对白

观察是否长期形成：

```text
A 问一个小点
B 答一个小点
A 再确认
B 再确认
A 问下一点
```

如果话语权本来没有变化，考虑合并，而不是强行保持互动气泡。

### 1.6 重复结算

观察同一结果是否连续通过：

```text
行动结果
+ 心理结论
+ 解释
+ 再总结
+ 章尾宣布
```

### 1.7 约束墓碑

观察正文是否专门证明：

- 某禁写项没有发生；
- 某能力没有升级；
- 某问题没有解决；
- 某奖励没有增加；
- 某人没有继续验证。

如果不影响当前行动，通常只是后台约束泄漏。

### 1.8 Uniform Completeness｜完成度过度一致

这是 v0.2 新增的语义级病灶。

观察一段连续正文是否长期表现为：

- 每次动作后都有心理解释；
- 每次情绪后都有原因说明；
- 每次异常后都有确认链；
- 每轮对白都把立场与原因说完整；
- 每个局部都在离开前做一次总结；
- 人物几乎不会暂时不知道、暂时不回应、暂时不处理。

```text
UNIFORM_COMPLETENESS
= many adjacent units repeatedly resolve to similar semantic completeness
```

它不是靠“短句比例”“省略号数量”判断的，也不能靠随机制造半句话来修。

诊断时问：

> **这些局部真的都需要在此刻完成到同样程度，还是模型只是习惯把每件事做完？**

## 2. 扫描输出建议

只输出：

```text
LOCATION
SIGNAL
WHY IT MAY MATTER
REVIEW_NEEDED: true
```

不要输出：

- AI 概率；
- 人类概率；
- 检测率；
- “必须改”；
- 自动重写全文。

## 3. 使用顺序

FIRST_DRAFT 默认不运行扫描器。

推荐：

```text
FIRST_DRAFT
→ 上游 Reviewer / 作者阅读
→ 有具体阅读问题时按需运行 scanner 辅助定位
→ LOCAL_REVISION
```

而不是：

```text
FIRST_DRAFT
→ scanner
→ 为清空所有 flag 全文优化
```

`UNIFORM_COMPLETENESS` 目前保持人工 / 模型语义诊断，不新增机械配额。脚本仍只抓明显表面规律。

## 4. 核心原则

> **扫描器是烟雾报警器，不是装修队。**
