# Suspense Execution Slice

> Writer 执行切片。只负责把主模型已经批准的悬念与信息边界写进当前场景，不负责设计新的谜题、误导、真相、伏笔或揭示时机。

## 输入权威

悬念相关信息只从以下来源取得：

1. `04_BOUNDARIES.md`：绝对禁止泄露的信息。
2. `01_OUTLINE.md`：本章批准的情节、揭示与停笔点。
3. `02_CURRENT_STATE.md`：人物当前知道什么。
4. `benchmark/EXECUTION_CARD.md` 的 `SUSPENSE` 模块（若存在）。

没有被上游批准的信息，不因为“悬疑需要”而自行补造。

## 1. 悬念的正文职责

Writer 只控制三件事：

- 信息出现的顺序；
- 当前视角人物注意到什么；
- 已批准线索在正文里写得多重、写到哪里停。

Writer 不决定：

- 真相是什么；
- 谁是凶手/幕后者；
- 新增假线索；
- 新增证据；
- 提前或延后批准的揭示；
- 为了刺激增加新危险。

## 2. 信息释放

- 先写人物实际接触到的异常，再让判断从证据长出来。
- 一个线索只需要完成当前场景的功能，不自动补“这意味着什么”的完整推演。
- 如果人物当前只能怀疑，就写成怀疑；不要替他升级成确定答案。
- 允许人物误判，前提是误判已经在上游输入中成立，或属于对现有可见事实的低等级自然猜测且不升格为真相。
- 读者已经能从画面发现异常时，不用旁白再盖章“显然不对劲”。

## 3. 未知感

未知不是靠故意省略关键事实制造，而是让“当前可知范围”保持真实。

可以：

- 人物看见结果但暂时不知道原因；
- 听见声音但不知道来源；
- 发现一处与既有认知不符的细节；
- 得到一条不足以闭合答案的信息；
- 当前问题被另一件更紧迫的事打断。

不可以：

- 叙述者知道答案却故意用假话骗读者；
- 把本应看见的明显事实强行藏掉；
- 为悬念让角色突然失智；
- 用“他不知道的是”越过视角提前预告。

## 4. 节奏

悬疑段不需要一直压短句。节奏跟随：

`发现 → 接触 → 反应/判断 → 新信息或阻断`

有时停在发现，有时停在行动，有时停在没有答案。不要每一拍都完成“异常 + 推理 + 结论”。

## 5. 与 Human Writing L2 的关系

Human Writing L2 优先：

- 问题可以暂时没有答案；
- 证据不必一次集齐；
- 人物可以只想一半；
- 解释只到当前行动所需程度；
- 不为了“悬疑感”机械制造碎句、停顿或故弄玄虚。

## 6. 自检

- 是否泄露了 `04_BOUNDARIES.md` 禁止的信息？
- 人物是否从不足证据直接跳到了正确答案？
- 是否新增了未批准证据/真相/危险？
- 是否把一个本来有效的异常解释得太完整？
- 本章结束时，知道多少是否与 `EXECUTION_CARD` / 大纲一致？
