# Hook Execution Slice

> Writer 执行切片。只负责把主模型已经批准的章首/章尾钩子落成正文，不负责选择新的钩子、改变停笔点、制造额外悬念或新增下一章剧情。

## 权威输入

钩子相关信息只从以下来源取得：

1. `01_OUTLINE.md` 的开场要求与批准停笔点。
2. `04_BOUNDARIES.md` 的禁止提前释放信息。
3. `benchmark/EXECUTION_CARD.md` 的 `HOOK` 模块（若存在）。
4. 当前题材卡与 benchmark 的表达节奏，仅作为“怎么落”的参考。

## 1. 章首钩子

Writer 可以：

- 把已经批准的冲突、异常、目标、危险、关系变化或行动结果尽快写到读者眼前；
- 选择从动作、对白、可见结果或当前问题切入；
- 压缩没有当前功能的背景铺垫。

Writer 不可以：

- 为了抓人增加大纲没有的新事故；
- 提前暴露后续底牌；
- 改变角色原本所在位置、状态或知识；
- 把普通章节强行改成危机开场。

## 2. 章尾钩子

章尾必须停在上游批准的功能位与停笔点。

可以通过以下方式落下：

- 一个动作刚产生结果；
- 一句对白改变当前关系或问题；
- 一条已批准信息出现；
- 一个异常被看见但尚未解释；
- 一个选择已经做出，后果留到下一章；
- 一个阶段目标重新变清楚。

不要在钩子之后再补：

- 意义总结；
- 下一章预告；
- “一切才刚刚开始”式升华；
- 额外一拍剧情；
- 为解释钩子而把悬念说透。

## 3. 钩子强度服从章节定位

不是每章都必须爆炸式悬念。

- 高压/推进章：批准的危险、反转、结果或问题可以形成强钩子。
- 关系/低压章：关系变化、未说完的话、阶段目标或细微异常即可。
- 收束章：允许以完成感、余波或新的已批准方向收尾，不强行制造事故。

Writer 不自行改变章节定位。

## 4. 与 Human Writing L2 的关系

钩子最容易被模型“解释坏”。因此：

- 结果已经成立就停；
- 读者能推断就不补结论；
- 不连续制造“漂亮金句 + 空行 + 总结”；
- 不把每章结尾写成标准化预告。

## 5. 自检

- 最后一拍是不是 `01_OUTLINE.md` 批准的停笔点？
- 是否多写了下一章内容？
- 是否为了更抓人新增事实/危险/人物？
- 钩子后是否还有一层解释或总结可以直接停掉？
- 章首有没有把必要背景压到不影响理解的程度，而不是删掉关键因果？
