# Decoding Policy

## 目的

正文生成是开放式写作，不是数学题。

当运行环境允许控制采样参数时，Writer 的解码策略应该保留一定语言选择空间，避免每次都落到模型最安全、最平均、最常见的第一选择。

这个文件只规定**方向**，不把某组参数写死成跨模型真理。

## 1. Writer 不默认使用纯确定性解码

对最终小说正文，若模型接口支持：

- 不默认 greedy；
- 不默认 beam search；
- 不把 temperature 固定为 0。

原因不是为了“随机”，而是为了允许多个合理措辞都保有被选中的机会。

但随机度必须服务可读性，不能为了多样性牺牲中文自然度和故事正确性。

## 2. 推荐方向

Writer 适合：

- moderate temperature；
- top-p 或 min-p 一类动态截断；
- 不把多个高随机参数同时拉高；
- 先保证高概率自然词仍然占主导。

具体数值必须按模型单独校准。

不同模型的 logit 分布、微调方式、量化版本差异很大，同一个 temperature 不能视为同一种“创作强度”。

## 3. 角色分离

### Context Compiler / Voice Analyst

偏确定性。

目标是稳定提取事实、标签、证据，不需要语言花样。

### Writer

允许适度随机性。

目标是自然、具体、有变化的正文实现。

### Blind Reader

偏确定性。

目标是读感诊断稳定，不因为采样随机每次换一套标准。

### Local Repair

低到中等随机性。

优先解决指定摩擦，不重新发明整段声音。

## 4. 不做整章 Best-of-N

默认不生成 4-8 个完整章节再让 Judge 选。

这会：

- 成本高；
- 容易让 Judge 偏好更“显眼”的版本；
- 鼓励模型追求可评分特征；
- 产生大量未审核 AI 草稿，增加自我污染风险。

## 5. 可选的 Local Variation

只有在极少数高价值语言节点，允许局部生成 2-3 个短候选后选择一个。

适合：

- 第一落点；
- 关键人物一句决定性对白；
- 一个重要心理转折的落句；
- 场景最后一拍。

不适合：

- 普通过渡句；
- 每一段；
- 整个微场景。

选择标准顺序：

1. 事实正确；
2. 中文自然；
3. 符合 POV / Voice；
4. 不自我炫技；
5. 与上下文衔接最自然。

不是选“最漂亮”的那句。

Local Variation 默认可关闭；没有验证收益前不得变成强制流程。

## 6. 没有采样控制时

很多云端模型不暴露 temperature / top-p / min-p。

此时：

- 不模拟随机错误；
- 不故意加口癖；
- 不故意加错字或不规范标点；
- 继续依赖 Voice anchors、人物注意力和自然中文核心。

“像人”来自选择机制，不来自人为制造瑕疵。

## 7. 参数属于模型适配层

未来若为某个具体 Writer 模型建立运行配置，参数写在独立 adapter/profile 中，例如：

```yaml
writer_adapter:
  model: ""
  decoding:
    temperature: null
    top_p: null
    min_p: null
    repeat_penalty: null
  notes: "经该模型专门验证后填写"
```

这些值不写进 `WRITE_CORE`，避免把某个模型的最佳参数误当成正文规律。

## 核心判断

Prose Engine 要控制的是：

> **可接受表达的分布范围。**

不是把模型锁到唯一句子，也不是为了“创意”把概率分布炸开。
