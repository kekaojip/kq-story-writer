# Prose Generation Loop

## 目标

把“已经确定的剧情语义”变成正文时，先生成**活着的场景**，再做有限的声音整形。

禁止使用：

`先生成完整 AI 稿 → 全文 humanize → 再全文润色`

这种连续全稿重写会不断抹平声音，并把模型自己的习惯反复强化。

## Pass 0：Semantic Wash

输入里可能有策划语言、功能标签和结构术语。

先只保留：

- 人物当下在哪；
- 谁在场；
- 已知事实；
- 当前想要什么；
- 必须发生的事件；
- 不允许发生的事；
- 场景结束时变成什么状态；
- 精确停笔点。

所有“爽点、杠杆、信息差、节奏节点、压力升级、决策树”之类标签在生成正文前失效。

它们只能帮助理解事件，不能进入正文语言。

## Pass 1：Scene Frame

在落字前形成一个非常短的内部场景框：

```yaml
NOW:
  place: ""
  pov: ""
  current_action: ""
  first_attention: ""
  immediate_want: ""
  pressure: ""
  unresolved: ""
  exit_condition: ""
```

这不是新的大纲。

它只负责防止 Writer 一开口就站到场景外面解释。

## Pass 2：Voice Resolve

读取：

- 当前 Voice Profile；
- 当前场景召回的 2-4 个 anchor；
- Chinese Prose Base。

只激活最多 5 条 voice traits。

不把完整风格模板、全部统计、全部禁忌一起塞进生成上下文。

## Pass 3：Lived Draft

第一次正文生成故意不追求“漂亮”。

目标只有四个：

1. 人物真的在现场；
2. 一拍自然带下一拍；
3. 叙事距离会跟着重要性变化；
4. 中文第一次就能顺读。

### 生成单位

按**微场景/注意对象**生成，不按字数固定切块。

一个单位通常结束于：

- 注意对象明显改变；
- 新人物接管互动；
- 当前动作产生结果；
- 人物做出局部决定；
- 时间/空间发生轻微跳转。

不要为了凑固定 300 / 500 / 800 字强行续写。

### 每个单位内部

优先使用局部微因果：

`刺激 → 反应/判断 → 动作/对白 → 反馈`

但不要求四项齐全。

如果当前一拍已经成立，立刻往下走。

## Pass 4：Distance & Voice Pass

完成一个微场景后，只检查两件事。

### A. Narrative Distance

有没有连续停留在“作者解释人物”的中距离？

高风险信号：

- 他知道……
- 他意识到……
- 他明白……
- 他分析……
- 这意味着……
- 对他而言……

它们不是禁词。问题是连续出现时，人物会从场景里消失。

修法只针对命中处：

- 直接给判断；
- 让判断落到动作；
- 让具体观察先出现；
- 让对白承担；
- 或干脆删掉已经被场景承载的解释。

### B. Voice Match

只比较当前微场景与 active traits / anchors 的“运动方式”。

不做逐句风格重写。

如果一段已经自然、清楚、符合人物，即使它很普通，也保持不动。

## Pass 5：Continuity Read

把相邻微场景连起来读。

只修：

- 重复起句；
- 主语突然不清；
- 前一段动作没有自然接住；
- 同一个信息被重新解释；
- 段落边界造成明显顿挫；
- 前后声线突然断裂。

不要借机“统一美化”。

## Pass 6：Blind Cold Read

冷读者只拿到：

- 正文；
- 目标读者；
- 必要的极少数世界词解释（只有完全不解释就无法阅读时）。

冷读者看不到 Outline、Scene Frame、Voice Profile、设计说明。

它只报告：

- 流是否断；
- 人物是否像活人；
- 哪句话需要脑内翻译；
- 哪段像作者整理答案；
- 哪里开始“意识到 AI 在写”。

## Pass 7：One Repair

只允许一次针对 cold-read findings 的局部修复。

优先级：

1. 看不懂 / 指代错；
2. 不自然中文；
3. 报告感 / 解释感；
4. 人物声音消失；
5. 节奏摩擦。

不追求 finding=0。

一个有个性的真人文本本来就可能有偏句、重复、突兀和选择性强调。

## 最终输出

正文输出不包含：

- 分析；
- Pass 标签；
- Voice 说明；
- 自检；
- 风格指标；
- “为什么这样写”。

只输出正文。
