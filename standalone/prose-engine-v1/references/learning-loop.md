# Learning Loop

## 目标

让模块随着用户真正的选择变准，而不是随着 AI 自己生成的文本越来越像自己。

核心规则：

> Learn from reviewed human decisions, not from raw AI drafts.

## 可以学习的信号

### 强信号

- 用户亲手修改一段，并明确认可修改后的版本。
- 用户明确指出“这种写法就是我要的”。
- 用户提供自己喜欢的正文样本并授权作为文风参考。

### 中信号

- 一段 Writer 正文经过用户明确 PASS，没有再要求语言返修。
- 同一种修改方向在多个章节反复出现。

### 弱信号

- Reviewer 认为没有问题。
- 检测脚本 clean。

弱信号不能单独进入 Voice Memory。

## 禁止学习

- 未审核 AI 初稿；
- 被用户拒绝的稿件；
- 正在返修的版本；
- detector 自己的规则描述；
- 细纲、策划卡、分析报告的措辞；
- 为测试临时生成但没有用户评价的样本。

这些可以作为 negative evidence，但不能作为正向声音样本。

## 从修改 diff 学什么

只提取可复用的**语言选择**，不记具体剧情内容。

例如用户把：

`他意识到事情比想象中严重得多。`

改成：

`这事比他想的麻烦。`

可以学习：

- 当前 voice 偏好直接判断；
- 少用“意识到”引导；
- 抽象“严重程度”优先换成人物自己的普通词。

不能学习具体人物、地点、事件。

## Preference Proposal

模块每次只能提出少量可复用候选：

```yaml
proposal:
  trait: ""
  evidence: ""
  confidence: low|medium|high
  scope: global|project|character
```

没有用户明确批准，不把 proposal 自动升级为永久规则。

## Voice Memory 控制

Voice Memory 必须短。

优先保存：

- 反复出现的稳定选择；
- 对读感影响明显的选择；
- 用户明确表达的偏好。

发现新偏好与旧偏好冲突时，不继续堆规则，优先合并或让新选择覆盖旧选择。

目标不是让 memory 越来越长，而是让模型越来越知道“这个用户在文字上真正会点头什么”。

## 防止自我污染

AI 生成 → AI 审核 → AI 宣布通过，不构成学习闭环。

至少需要一个外部认可信号，才能进入正式 Voice Memory。

这样可以防止模型把自己的默认腔误认为“作者风格”，然后越写越重。
