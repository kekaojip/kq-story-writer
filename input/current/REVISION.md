# 第001章修订任务

状态：REWRITE（局部修订，不推倒重写）
目标：保留当前版本已经成立的生活感、人物对白和场景流动，只修正以下问题。

## 1. 开场进入异常现场太慢

当前版本先写接电话、穿外套、骑电动车、进小区、上楼，生活感是好的，但番茄男频第一屏抓力被削弱。

修改目标：
- 明显压缩“接单→赶路→上楼”过程。
- 尽快进入“五楼困人现场 / 老周坚持电梯没停六楼”的核心冲突。
- 可以保留老陈、槐安里、深夜旧楼这些生活化质感，但不要让它们占据开头主要篇幅。
- 不要求改回另一个版本的“别按一楼”开头，自行寻找更自然、更快的切入方式。

## 2. 不要把任何信息源提前写成绝对可靠

当前版本出现“控制器不会说谎”“监控做不了假”这类绝对判断，会削弱本章真正的核心：三套现实证据彼此冲突，主角必须继续验证，而不是先认定其中某一套是真相。

修改目标：
- 删除或弱化所有“某个设备绝对不会错/不会造假”的结论。
- 林砚只能判断“目前没有发现正常故障迹象”“这份记录暂时可信”“三套证据无法同时成立”。
- 保持主角验证欲强，但不要让他在证据不足时表现成全知。

## 3. 减少解释性收束，优先让事实自己成立

当前版本有少量段落会在已经写清楚后，再替读者总结一次，例如连续说明“三样东西如何互相冲突”“这不是烧屏也不是反光”“普通故障解释不了”等。

修改目标：
- 已由动作、数据、视觉结果表达清楚的信息，不再追加同义解释。
- 保留必要判断，但尽量落在林砚下一步行动或选择上。
- 不追求把每一个异常都解释完整。
- 不要为了“去AI味”机械删短句，重点是删重复意义。

## 4. 保留当前版本真正有效的部分

以下部分不要因为修订而丢掉：
- 老周的口语感和现实反应。
- 老陈作为物业值班员的生活化功能位。
- 旧居民楼、设备间、门机、编码器等具体职业场景。
- “人说没停 / 监控显示停过 / 机械记录少一层”的三证据冲突。
- 林砚先验证、后判断的可靠型主角感。
- 章尾必须仍然停在：显示屏没有6，广播却说“六楼到了”，门开始打开。

## 不得修改

- 不新增核心人物。
- 不新增组织、能力、怪物或新的世界规则。
- 不确认六楼真相。
- 不解释能力来源或能力名称。
- 不提前使用“修补”能力。
- 不改变本章核心事件顺序和最终钩子。

- 修订申报写入 `output/current/report_v2.json`。
- 完成后停止，不继续下一章，不修改 input、Skill、Tracking 或其他文件。
